# План внедрения и развития

## Кому нужна система

| Кто | Что получает |
|---|---|
| АФМ, подразделение по противодействию пирамидам | Очередь групп с признаками, сети связанных групп, отчёт с цитатами для дела |
| Банки и Kaspi | Реквизиты получателей из помеченных групп — сигнал для своего антифрода |
| Модераторы площадок и сообществ | Раннее предупреждение о группах с признаками схемы |
| Граждане | Бот «проверь сообщение»: переслал подозрительный текст или скриншот — получил признаки и совет |

## Как данные попадают в систему

Только законными путями:

1. **Жалобы граждан.** Бот в WhatsApp и форма на сайте: пересылка сообщения, скриншота или экспорта чата. WhatsApp закрыт, поэтому его данные приходят только так.
2. **Открытые Telegram-каналы и группы** — через официальный API, только публичные данные.
3. **Материалы проверок**, которые ведомство получает в рамках своих процедур.

## Работа аналитика

1. Группы приходят в очередь, сверху — высокий риск.
2. Аналитик открывает карточку: почему помечено, цитаты, роли, реквизиты, связанные группы.
3. Аналитик решает: «Признаки подтверждены» или «Ложное срабатывание», при необходимости выгружает отчёт.
4. Решения аналитиков становятся новой разметкой. Раз в неделю модель переобучается, а новая версия проверяется на свежем слепом наборе, прежде чем её выпустить.

## Этапы

| Срок | Что делаем | Результат |
|---|---|---|
| 0–1 месяц, пилот | Разворачиваем в контуре партнёра, загружаем 500–1 000 обезличенных групп из жалоб, размечаем, переобучаем. Запускаем бот для граждан | Ложных срабатываний не больше 3% на реальных данных |
| 1–3 месяца | Мониторинг публичных Telegram-каналов. Обмен с банками хэшами реквизитов. Распознавание речи для голосовых и стримов (казахский и русский). Узбекский язык для юга страны | Охват Telegram и голосовых, сигнал банкам |
| 3–6 месяцев | Граф сетей на уровне страны, раннее обнаружение по росту групп и повтору рассылок, API для площадок | Пирамиду видно в первые дни, а не после жалоб пострадавших |

## Масштабирование

- **Скорость.** 0,22 мс на сообщение на одном ядре процессора: около 4 600 сообщений в секунду, порядка 400 млн в сутки. Модель — файл весов, видеокарта не нужна.
- **Архитектура.** Приём (бот, API, экспорты) → очередь сообщений → независимые обработчики анализа, которые добавляются горизонтально → база данных и граф связей → дашборд аналитика.
- **Мультимодальность.** Скриншоты чеков и переписок распознаются (русский и казахский), голосовые и стримы — через распознавание речи. Дальше работает тот же конвейер признаков.
- **Новые языки.** Правила написаны по «каноническому» тексту, поэтому язык добавляется словарями: узбекский, кыргызский.
- **Новые схемы.** Формулировки меняются — обратная связь аналитиков даёт новую разметку, правила и веса версионируются, у каждой версии есть метрики на свежем слепом наборе.

## Риски и как их снимаем

| Риск | Что делаем |
|---|---|
| Персональные данные | Реквизиты маскируются в интерфейсе, данные хранятся в контуре заказчика, доступ по ролям, журнал действий, срок хранения |
| Ложное обвинение | Система не выносит вердикт; любые меры — только после проверки специалиста |
| Обход правил маскировкой | Нормализация снимает разрядку, двойники букв и цифр, транслит; новые приёмы попадают в правила через обратную связь |
| Правила площадок | Только открытые данные и материалы, которые передали сами пользователи |
